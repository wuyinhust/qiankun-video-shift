# 两步升级与验证（2026-10-03）

基线：`cacb13d60022324f353e1cb0fd8699ed2c32c596`。方法来源与固定版本见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。

## 1. 增加可复用能力

- 吸收 gnipbao 的证据绑定、视角/接触/遮挡/截止状态纪律，分离首帧与运动，并从单一事实源编译通用及五种 H3 格式。
- 吸收 Hypit 的问题驱动观察、跨镜视听系统、语义锚点、完整角色替换和已接受素材复用。与 gnipbao 重叠的方法只集成一次。
- 原声保真交接记录实际流和时间原点；分析用 WAV 不冒充原音轨。实际输入改变会使旧复核失效。
- 实现独立的 v2 契约、编译器、校验器和局部证据索引，无第三方引擎、运行时或模板拷贝。

## 2. 精简为三条路径

| 路径 | 必要工作 | 省去的重复工作 |
|---|---|---|
| 快速反推 | 源视频 → 实际观察 → 通用/所选模型 Prompt | 未请求的变体、完整报告、H3 手册、制作系统 |
| 原创迁移 | 复用事实 → 结构公式 → 替换映射/目标 Prompt → 制作交接 | 重复描述事实、安装生成引擎、照抄源时钟 |
| 局部修订 | 按 shot/fact/job/system 读取 → 检查邻接转场 → 修改/编译/复核 | 全片重读、重新下载/抽帧、重做已接受素材 |

入口、参考文档去重；新任务有最小填写示例。媒体管线批量抽帧，以实际解码 PTS 记录时间；缓存同时核对源、参数和产物哈希。RGB 检测补上暗色/色相变化，保留真实首末帧及短尾卡。自动分镜仍需实际观察纠正。

## 验证结果

`python3 -m unittest discover -s tests -v`：**44 项通过，0 项跳过**。覆盖派生内容篡改、事实缺失、音频渠道、运动证据、首尾覆盖、目标/源分离、复核失效、五种 H3 路由契约、生成段能力约束、实际音频流/PTS、局部读取及邻接转场。

真实 FFmpeg 集成测试使用原创合成视频：25/10 fps 混合帧率、红/蓝/黑三镜、0.4 秒黑场尾段、合成音频。验证实际帧时间、尾帧像素、默认切点、哈希和缓存不改产物。Skill 格式检查及 `git diff --check` 通过。

独立前向试用在另一段原创 8 秒合成视频上完成“英文通用反推 → 第二段换绿 → 原创品牌色制作方案”三条路径。实际查看 10 张证据图并完整解码 200 帧，三个分析均通过文件/当前复核检查。换绿只改变三条目标描述，源事实、时间、结构和尾态不变；后两条路径未重新解码或抽帧。首次试用暴露的漏切、源码阅读负担及全片 job 读取问题已修复并窄范围复核；入镜颜色也通过邻接 `boundary_facts` 纳入修改范围。

读取量按 Unicode 字符计数，是指令加载量指标，**不是实测模型 token 或费用**。旧版要求加载的入口与参考共 15,973 字符；新预算包含最小示例，H3 外部官方指南两边均不计入。

修订预算包括入口和按需制作参考；已有项目不重复读取契约。实际事实/证据的上下文量另受任务范围影响。数字与方法保存在 [efficiency.json](efficiency.json)，原文档基线在 [baseline.json](baseline.json)。

同一 8 秒三镜视频、相同 `--scene-threshold 0.05 --no-audio` 参数的一次本地计时：旧冷运行 0.834 秒、新冷运行 0.637 秒、复用运行 0.169 秒。新旧镜头范围及代表帧 RGB 相同，缓存运行的清单字节不变。早期样本为 1.212/0.648/0.160 秒；计时有波动，只证明该样例减少重复工作，不推广为所有视频的速度倍数。
